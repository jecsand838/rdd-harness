# Native filesystem qualification

## Required capability

FR-020 requires complete publication or preservation of the previous destination, including interruption and an uncertain outcome. NFR-PRIV-002 restricts selected-file access; FR-019 and FR-023 require independent, complete backup data. This experiment qualifies Darwin filesystem primitives for the proposed internal-SSD APFS destination scope on REF-MAC-M3MAX. It implements no Todo operations and does not satisfy packaged application acceptance.

## Candidate and sources

Use Rust standard file operations plus Darwin `renameatx_np` for atomic publication relative to an already opened destination-directory descriptor. The native chooser supplies the selected file; the UI receives an opaque operation token, not arbitrary filesystem capability. Production implementation semantics remain in the main solution specification.

Primary sources were read on 2026-10-08:

| Source | Bounded finding |
|---|---|
| [Apple XNU rename manual](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/rename.2), and the installed SDK 27.0 `usr/share/man/man2/rename.2` | Same-filesystem rename provides atomic destination replacement. Relative names can use directory descriptors. `RENAME_EXCL` fails if the target exists; the filesystem must support its capability. Nonzero return requires error handling. |
| [Apple XNU filesystem attributes](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/attr.h), and installed SDK `usr/include/sys/attr.h` | Filesystem capabilities include `VOL_CAP_INT_RENAME_EXCL`; reject unsupported publication mechanisms before modifying a destination. |
| Installed SDK 27.0 `usr/share/man/man2/fsync.2` and `usr/include/sys/fcntl.h` | `fsync` does not establish a universal power-loss guarantee; `F_FULLFSYNC` additionally asks the drive to flush its buffers. The experiment checks both return values. |

No external filesystem library is added by this experiment. It uses Rust 1.99.0's standard library and the OS-provided Darwin interfaces. The checked constants match SDK 27.0 headers (`RENAME_EXCL=4`, `F_FULLFSYNC=51`). Neither the SDK nor copied third-party source is redistributed. The production dependency inventory must separately justify any selected Rust FFI binding.

## Reproducible experiment

Run `python3 experiments/spec-filesystem/run.py`. The runner invokes `rustc --edition=2024 -D warnings` on [the Rust probe](../../experiments/spec-filesystem/probe.rs), creates only disposable fixtures under ignored `target/spec-filesystem`, and removes its own fixture directory on completion. `--record` updates specification-time evidence while specification is open; ordinary reproduction does not rewrite the accepted evidence files.

The fixture consists of deterministic UTF-8 JSON bytes identified as old (65,568 bytes) and new (131,106 bytes), generated by the source. A sibling temporary file is created exclusively with mode 0600, written, synchronized with `sync_all` and `F_FULLFSYNC`, and compared byte-for-byte before publication. Directory synchronization also succeeds on the actual reference filesystem.

| Case | Independent observable oracle | Observed |
|---|---|---|
| Existing target without replacement permission | `EEXIST`; both old target and complete candidate remain byte-identical | Passed |
| Existing target with replacement | Target equals all new fixture bytes; candidate name disappears | Passed |
| New target without replacement | Target equals all new fixture bytes | Passed |
| Managed-file aliases | Hard link has the same `(device,inode)`; symlink canonicalizes to the managed fixture and shares identity | Passed; this proves detection primitives, not production rejection |
| Abrupt termination before publication, three repetitions | Child reaches controlled checkpoint then receives SIGKILL; target equals all old bytes; pending journal and complete temporary remain | Passed |
| Abrupt termination after publication but before acknowledgment, three repetitions | Child receives SIGKILL at controlled checkpoint; target equals all new bytes; pending journal exists; temporary name is absent | Passed |

The synthetic journal deliberately remains pending at both cut points. The parent reconciles against actual destination bytes; journal presence alone is never a success result. The worker has no successful acknowledgment before either kill. This proves that the proposed publication and reconciliation primitives are feasible, not that an application operation journal is implemented.

[Machine result](../../experiments/spec-filesystem/results.json) records source SHA-256 values, command, compiler identity, and exit code. [Transcript](../../experiments/spec-filesystem/transcript.txt) records each actual result. [Reference-host inventory](reference-host.json) records the APFS/SSD and SDK environment.

## Design consequences and limits

Keep temporary publication on the selected destination filesystem. Never truncate the old destination while constructing a backup. Use no-clobber publication until replacement is confirmed; if a previously absent destination appears, preserve it and obtain confirmation. Native alias checks need both canonical path handling and device/inode comparison, including protected files that do not yet exist, managed directories, and hard-link aliases. A directory descriptor used for one selected operation does not expose a general UI directory grant.

The full implementation must retain sufficient private operation metadata to reconcile an interrupted publication before retry, validate complete backup semantics, handle failure after rename as an uncertain result, enforce destination restrictions, and prove scope in its actual native adapter. These obligations are not fulfilled by this probe. No power-loss, kernel-failure, concurrent hostile same-account modification, network-storage, external-drive, or performance result is claimed. The application interruption matrix and its required repetitions remain mandatory. Changes to the SDK, filesystem policy, synchronization strategy, or publication API require requalification.
