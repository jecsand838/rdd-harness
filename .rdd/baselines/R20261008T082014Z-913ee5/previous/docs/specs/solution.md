## Domain and state

One collection domain owns all task validation, transitions and query rules. Its private `TaskId`, `Title`, `Notes`, `CalendarDate`, `TaskStatus` and `Task` types are created only through validated constructors. Protobuf is the boundary representation, never the invariant owner. Native validation is authoritative; the UI may display consistent feedback but cannot bypass native rejection.

IDs are 128 random bits encoded as exactly 32 lowercase ASCII hexadecimal characters, opaque to users. Create checks collision against the committed collection and redraws before commit. Canonical order is ascending lexicographic ASCII bytes. Operations use separately generated IDs of the same form. A deliberate later create has a new operation ID even when its content is identical.

Titles and notes follow requirements Section 3. Unicode whitespace is Unicode 16.0.0 White_Space: U+0009–000D, U+0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F and U+3000; use this explicit set so a compiler Unicode update cannot alter trimming. The [Unicode16 PropList](https://www.unicode.org/Public/16.0.0/ucd/PropList.txt), accessed2026-10-08, lists these25codepoints. Trim title/query boundaries; after trimming reject title internal LF, CR, VT, FF, NEL, U+2028 and U+2029 and U+0000; internal tab and other permitted whitespace survive. Notes replace CRLF then remaining CR with LF before counting scalar values and rejecting NUL. There is no silent truncation. Restore applies these same normalizations before count/value validation and confirmation. Export emits already normalized values. Due dates are exactly ten ASCII characters `YYYY-MM-DD`, proleptic Gregorian years 0001–9999 with leap-year validation; no timezone conversion applies.

UTC instants use signed seconds since Unix epoch plus nanoseconds 0–999999999 (`google.protobuf.Timestamp`, years 0001–9999). Backup emits UTC RFC3339 with `Z` and exactly nine fractional digits. Restore accepts RFC3339 UTC `Z` with zero through nine fractional digits and canonicalizes without losing precision. No ordering relation between created, updated and completed timestamps is imposed: a real clock correction may make updated precede created or completed. Presence/status consistency is mandatory. Completed requires a completed timestamp; Open forbids it. Create samples one native UTC instant for both created and updated; state transition samples one for updated/completed; edit preserves completed. Identical normalized saves and repeated set-state return committed no-op without changing task timestamps.

Search transforms trimmed query and candidate title/notes with Unicode 16 NFC followed by default full non-Turkic case folding. Match the entire transformed query as a literal contiguous substring of either independently transformed field. Empty query imposes no restriction. Diacritics remain significant; stored bytes are not rewritten. Ordering and filter semantics come directly from FR-010–FR-013, with the ID ordering above completing ties.

Application state is Starting, Ready, StorageBlocked or Closing. Mutation admission is Idle, Pending(operation), Uncertain(operation), then resolved Idle. Only one mutation or restore is admitted, atomically before spawning work. Repeated same in-flight operation returns its existing status; a different concurrent mutation is Busy, never queued. Reads use an immutable committed snapshot and remain available. A query response includes generation, total collection count and matching count; stale completions cannot replace a newer query result. Export has a separate one-job admission slot, using one immutable committed snapshot; it may run during a mutation and must reflect a whole pre/post state. Restore is a mutation.

## Modules and enforced boundaries

The proposed logical modules are intentionally few; preparation chooses exact source files within these owners. There are three compilation units: a native core library (collection/application/storage/backup logical modules, with Collection framework-independent), Rust/WASM UI, and Tauri executable. The generated crate remains excluded from outer workspace membership and is consumed by path. A crate per task/table/service is rejected because it provides no additional business invariant. No generic repository framework, DI container, network server, sync layer, event bus or plugin abstraction is introduced.

| Owner | Responsibility and provided contract | Dependencies and forbidden access | Why separate |
|---|---|---|---|
| Collection | `CollectionService`: validate snapshots, evaluate one transition, select query results; owns task invariants | Generated contract/value libraries only; no Tauri, file I/O, SQL, clocks or network | One invariant owner, deterministic tests |
| Storage | `StorageService`: open, read committed snapshot, transactional commit, inspect receipt, close | Collection validation and embedded Turso; no UI | Sole database owner and durability boundary |
| Backup | `BackupService`: native file selection, JSON parsing/serialization, safe publication, retained candidate | Collection validation, approved native dialogs/filesystem; no SQL/UI state | Explicit untrusted-file and publication boundary |
| Application | `ApplicationService`: admission, clocks/IDs, receipts, restore/deletion confirmation, lifecycle | Collection, Storage, Backup; no direct SQL | Coordinates independent effects and makes acknowledgment precise |
| Desktop | Window startup/instance arbitration, command authorization/byte transport, private diagnostics | Application and generated contracts; storage constructed only through composition root | Framework adapter, no duplicated rules |
| UI | Leptos Rust state/events, rendering and accessible journeys | Generated messages and typed application transport only; no native core, Turso, file/shell/HTTP APIs | WASM boundary prevents native authority leaking into view logic |

All named service providers implement generated traits; associated `Error` maps exclusively to the frozen `Failure` taxonomy. Application failures normally travel in typed response fields, not transport exception strings. Unexpected transport failure becomes Unknown outcome for a submitted operation, never inferred rollback. UI transport has one typed method for every `ApplicationService` method, encodes its generated request and decodes its generated response. Each Tauri command delegates to that trait method. Production registration inventory must exactly match the ten methods. `C-ARCH` verifies dependency allowlists, provider implementations, UI typed callsites, command inventory, no raw SQL outside Storage, no native filesystem calls outside Backup/Storage/diagnostics and Desktop’s narrowly scoped instance lease/activation mailbox and no first-party JavaScript application behavior. Deliberately inserted forbidden imports, command names and direct SQL/UI paths must make this checker fail in its own fixtures.

## Operation inventory and semantics

All commands are restricted to the bundled `main` window and its local origin. Malformed protobuf, missing required messages/oneofs, zero/unknown enum values, invalid IDs, invalid timestamps and semantically invalid inputs reject before effects. Every response has exactly its declared result branch; an absent error in a success-only response means success. All `Failure` fields are safe metadata: allowlisted field name, one-based backup record index, random correlation ID. No raw SQL, exception text, title, notes, due date, selected path or backup bytes enter diagnostic errors.

Create/edit carry full content (empty notes and absent date mean clear); there is no partial patch ambiguity. Delete confirmation tokens, candidate tokens and destination tokens are cryptographically random, process-local, single-use and bound to their exact resource; they are not paths. Unknown/expired tokens return StaleToken. A normal restart invalidates tokens and UI drafts. Each native process creates a random session ID exposed by Query; mutations, reconciliation, restore and export require that ID. Prior-session submissions reject without effects. Storage keeps the latest durable receipt together with its input digest and outcome, atomically with generation, sufficient to resolve the single terminal uncertainty on recovery. Application retains the latest response and a set of all admitted IDs for its current session; older seen IDs reject as stale, and the latest ID returns its established outcome. Reusing an ID with different input rejects. There is no content-based deduplication. No public network or external caller is supported.

Export replay uses `Export` again with the same session/operation ID: it inspects the retained publication receipt and resolves old/new destination identity/digest without reopening the chooser or writing a second backup. It returns the original saved location/count on established success, a confirmed rejection when the old destination remains and no publication occurred, or Uncertain while inaccessible. A different export ID is Busy until this resolves. Backup `Publish` has the same replay semantics on its retained operation/token. Startup reconciles a pending publication journal before admitting exports; previous-session UI requests then reject and normal UI communicates the recovered outcome. Paths are retained privately only as needed for this recovery, never diagnostics.

## Storage and recovery

Native backups may use the native dialog plugin within Backup; this does not permit Tauri imports in Collection or UI filesystem access. Desktop supplies the authorized app/window handle at composition and owns plugin registration.

Native data directory is `~/Library/Application Support/com.rdd.todo/`, mode 0700, with database and sidecars mode 0600. Diagnostics are a mode-0700 child. Paths derive from the current account; no UI path override. Startup creates only when both application storage marker and database are genuinely absent. If an existing marker/database/sidecar exists but cannot be opened or validated, stop and preserve it. A new store is initialized transactionally with metadata `format_version=1`, generation zero, tasks and operation receipt. Unknown future versions reject. Before opening an existing original with write-capable engine handles, hold the instance lease, check actual native read/write authorization for the original files and their containing directory (a successful copy is not proof of writability), and copy only its complete known stable database/sidecar set to a mode-0700 private preflight directory with mode-0600 files. Inspect/recover only that copy to validate format version and task invariants. A failed copy/open/version/integrity check preserves every original byte and enters StorageBlocked; no preflight copy is ever promoted over the original. Only successful validation permits the authoritative original to open with the qualified settings. This avoids assuming that merely opening a corrupt/future file is read-only. Preflight files are confined managed temporary data and protected backup aliases. Initial schema fixtures are preserved; there is no prior released migration in release one.

Tasks use identity primary key, text content, optional calendar-date text, status, timestamp seconds/nanos and nullable completion columns. Metadata stores format version/generation. A bounded latest-operation receipt contains operation ID, digest, outcome and affected ID. SQL parameters carry all untrusted values. Normal mutations and replacement are single real Turso transactions; capacity validation is against the same expected generation. Replacement deletes/inserts within that transaction and updates receipt/generation atomically; an empty replacement is valid. Idempotent content/status saves can record a receipt without changing task timestamps or collection generation. In-memory committed snapshot swaps only after confirmed commit. The database remains authoritative; snapshot caches are rebuilt and validated after reopen.

Database runtime settings, transaction API, fsync semantics and observed probe results are selected in `dependencies.md`. The absence of a receipt only resolves rejected after the engine has completed recovery and the terminal transaction is confirmed absent; an I/O error cannot itself establish rejection. On uncertain outcome, keep input and operation identity, stop all conflicting writes, retry only reconciliation with bounded delay and an explicit user retry action if storage remains unavailable. Normal close stays waiting; forced exit uses requirements Section 7. No automatic empty replacement or corruption repair.

One native async owner controls the database lifecycle; use Tauri's Tokio runtime, a one-slot admission state and immutable committed snapshots. CPU-heavy snapshot validation, serialization and file work run on a bounded blocking worker (one per backup job) rather than blocking the UI or async scheduler. Track joins; closing first stops admission, resolves admitted work then closes. Background calendar timer is cancelled and joined. No task is considered cancelled merely because its handle was dropped.

## Backup format and file access

Version 1 is UTF-8 JSON object `{format:"todo-backup",version:1,tasks:[...]}`. Every task has exactly `id,title,notes,due_date,status,created_at,updated_at,completed_at`; null is required for absent date/completion. Status strings are `Open` or `Completed`. Required fields cannot be omitted; duplicate JSON keys, trailing data, unknown format/version and wrong scalar types reject with document/record/field condition. Unknown fields reject in version 1 to expose typos and incompatible data. Timestamp/date/identity grammar is above. Export order is identity ascending. JSON escaping is standard; no lossy byte conversion. Selected file validation preserves its original bytes; the retained normalized candidate supplies the later transaction.

Parser streaming limits account for the supported maximum: 10,000 tasks × 10,200 Unicode scalars plus metadata. A 3 GiB input-byte limit allows worst-case JSON Unicode escaping and permitted JSON whitespace within that bound; this finite defensive bound is a document condition, never silent truncation. Unbounded irrelevant whitespace is not required interchange. Enforce task count while parsing; allocate no more than one selected candidate and one export snapshot. Capture candidate digest over selected raw bytes, then store the validated normalized values and counts. Confirmation labels the exact selected file and both counts; no file mutation occurs during restore.

Supported export destinations are ordinary writable files on the reference Mac's internal APFS SSD. Network, external/removable, non-APFS, alias/symlink and special-file destinations reject before modifying an existing file. This is the selected storage support policy permitted by FR-020. Native selection authorizes only the selected file plus narrowly scoped sibling temporary/publication artifacts. Managed database, sidecars, recovery/migration and diagnostic directories are excluded by canonical parent/path and device/inode identity (hardlinks included). `filesystem-qualification.md` defines atomic sibling publication, no-clobber and outcome reconciliation. No destination is opened with truncate. An operation receipt retains selected destination identity and old/new digest only for publication reconciliation; sensitive path is not logged. Stale safe temporary artifacts are cleaned only after outcome is established.

## UI, lifecycle and local help

Leptos renders semantic HTML in the bundled Tauri WebView using a fixed light appearance and bundled/system fonts. Query pages contain task summaries (ID/title/status/due date) only, with default limit 100 and allowed limits 1–200; zero uses 100. Native applies the complete predicate/order before slicing, and matching_count always describes the full result. The initial offset is zero; subsequent pages require the returned generation, with mismatch producing StaleToken and restarting at page zero. Offset beyond the result returns an empty page with the correct full count. GetTask retrieves the full fields for one selected task. Accessible previous/next controls, result/page labels and keyboard navigation reach every result. Full notes collections never cross the WebView IPC boundary. UI transport trims title outer Unicode whitespace before encoding while retaining the exact unsubmitted/submitted editor input for correction and draft decisions; native independently repeats the authoritative normalization. Native cannot reject an otherwise valid Query or Mutation solely for raw envelope length: both query canonical decomposition and title outer whitespace can exceed normalized field bounds. Native enforces semantic field limits after normalization. Actual allocation/transport exhaustion becomes an actionable operational failure retaining input, never a silent empty result, invalid-field assertion or claimed rollback. Non-text control messages validate exact bounded IDs/tokens and fields. Summary Protobuf responses stay below 256 KiB and GetTask below 64 KiB; their JSON byte-array IPC representations have a 4× allowance. Backup contents are processed natively. These limits cover all valid maximum-length scalar values.  Initial state is Open / Any / empty search / newest created on every launch and successful restore. Task rows expose title/status/due date and an inspect/edit action. The editor remains pinned when query constraints hide its task; changing views never discards a draft. Dirty means exact editable input differs from its opening/last-acknowledged form, even if normalization would produce no stored change. Switching selected task, new create, cancel, restore or close while dirty opens retain/discard guard; retain cancels the original action. Submitted editor state is retained through pending/rejected/uncertain results. Mutations disable conflicting controls at admission, show pending immediately, and show an accessible busy announcement by 500 ms if still pending. Reads/focus/window interaction remain active.

Native Today is sampled on startup, every 30 seconds while active, and on focus/resume before rendering date-dependent results; native clock/timezone is authoritative. Refresh after focus/resume must settle within one second. Tests use injectable clock only in instrumented builds; release has no clock-control command. Stored calendar dates never change due to timezone.

Draft and confirmation dialogs use named headings, focus containment, Escape/cancel, visible focus and meaningful focus return. Status is conveyed in text/icon labels rather than color alone. Inline errors connect to their controls (`aria-describedby`), focus first invalid input, and a polite live region announces success; urgent failures use an accessible alert. Virtualized lists, if needed for capacity, retain semantic list/row names and a keyboard path to every result and count; implementation must qualify VoiceOver and must not make offscreen tasks unreachable. Text resizing reflows editor/controls with scroll access at 200% in 1280×720. A Rust-controlled View → Text size menu exposes 100%, 150%, 200% and Command-plus/minus shortcuts; the per-launch default is 100%. This is delivered functionality enabling the required resizing, not a developer-tools override.

Before opening any database or sidecar, Desktop acquires a nonblocking exclusive Darwin `flock` on a mode-0600 `instance.lock` file inside the mode-0700 canonical account/data-location directory. The open file descriptor is retained for the process lifetime, including Closing; never unlink or replace the lock file, since that would create a second lock identity. A failed lock acquisition never opens storage. The selected Tauri single-instance plugin was rejected because its global `/tmp` socket, asynchronous bind fallback and lack of activation acknowledgment do not establish these guarantees; no such plugin is included.

A secondary writes a unique random-nonce activation request into the account/data-location's mode-0700 `activation/` directory, with mode-0600 files and atomic publication. The primary polls at 50 ms while its native loop is alive, dispatches `show`/`set_focus` on its main window, and only after successful callback completion publishes an ACK bound to that nonce. It processes a bounded batch of 32 requests each tick; requests carry only protocol version and nonce, never paths or task content. This is private filesystem IPC, not a socket/HTTP server or outbound network connection. A secondary waits at most ten seconds for its matching ACK, then exits; timeout/focus failure is actionable and fail-closed, never permission to open a second writer. While waiting it may attempt the same lease: only successful acquisition after owner exit permits normal startup. OS process termination releases the lease. A Closing primary focuses its waiting/closing window before ACK and retains the lease through database closure and process termination; secondary exits after that ACK. No lifecycle race permits bypassing the lease. Existing drafts are never submitted, discarded or reinitialized by activation. Stale mailbox entries can be cleaned only by the acquired primary, using exact protocol-named files; they never imply lease ownership. All instance files are protected backup aliases.

`instance-qualification.md` records actual native contention/ACK/crash-takeover feasibility; the full sequential/simultaneous launch and draft-preserving activation remains delivered-package FR-024 acceptance. Package is local ad-hoc-signed `.app`, installed/copied to the current user's Applications directory; no notarization or public distribution claim. Runtime has no compiler/dev-server/CLI dependency. Release resources include help text covering all FR-025 topics, actual app version from Cargo package metadata and actual account data/backup locations; user-selected paths may be displayed in the UI but never logged.

## Security, diagnostics and compatibility

Production loads only bundled UI and static help/fonts. CSP restricts default/script/style/image/connect origins to required local Tauri asset/IPC protocols and permits only the qualified WASM loading exception; no remote URL, HTTP server, shell, updater or generic filesystem permission. Release has exactly one window, explicit app-command permissions and no frontend dialog/fs plugin access; native approved operations own dialogs. Dev/test helpers are separate build features absent from the delivered dependency/command inventory. Security tests directly attempt forbidden commands/origins, malformed protobuf and semantically over-limit fields (not merely large valid raw Query/Mutation text) and markup/SQL-shaped text. Process-attributed observation distinguishes OS connections from app traffic.

Diagnostics contain only timestamp, severity, app version, operation category, random correlation ID and allowlisted outcome/error code. Local append/rotation uses five files of at most 2 MiB inclusive, caps oversized events, and never follows externally supplied paths. Failure to create/write/rotate diagnostics is swallowed after safe bounded handling and cannot fail a valid task operation. Seeded private values and selected paths must be absent from all logs, panic output and crash diagnostics controlled by this application. There is no upload.

Package version starts 0.1.0; storage/backup version starts 1; Protobuf package is `todo.v1`. Never reuse deleted field numbers/names; reserve them. Unknown enum values reject; incompatible semantics or schema changes require a new specification run and version decision. `rdd.v1` remains a harness-only contract, not an application dependency. Contract proofs, fixture identities, human platform protocols and all requirement mappings are frozen with this baseline. Product acceptance remains future work; no specification probe claims that Todo functional, accessibility or performance requirements already pass.
