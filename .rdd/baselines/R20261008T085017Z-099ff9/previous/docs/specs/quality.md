## Recovery

Run exactly 6 classes × 3 cut points × 20 independent repetitions = 360 kills on the reference Mac: create, edit, complete, reopen, delete and whole restore. Each trial resets outside observation to a known small dataset; acknowledged prefixes include superseding edits/deletes/restores and legitimate clock correction. The runner, outside the killed process, stores submitted normalized values and observed acknowledgments in a synchronized ledger. It computes expected history with independent fixture transitions, not the app's receipts, SQL/query implementation or returned snapshots.

The instrumented application checkpoints are (A) after transaction preparation but before commit starts; (B) after actual commit begins, at the qualified WAL `File::sync` barrier before commit returns; (C) after the external runner observes the acknowledgment, durably records it and signals its kill barrier. Parent-controlled barriers and actual checkpoint/engine traces make the selected point deterministic; no sleep before commit substitutes for B. At B the runner arrests the process at the actual qualified engine barrier, then SIGKILLs it. SIGSTOP sampling is supplementary trace evidence, not a claim that arbitrary sampling hit commit. No acknowledgment is released at A/B. The app never stores the independent ledger.

After each kill reopen using the actual persistent locked engine and compare all identities/content/timestamps/status to ledger replay. Every acknowledgment is represented in admitted order subject to later supersession. Only the terminal unacknowledged operation can be wholly old or wholly new; partial fields/collections are never valid. Keep one keyed record for every class/cut/repetition, with checkpoint confirmation, engine/hook identity, PID, kill result, ledger and reopened semantic digest. Power/OS/device failure and hostile same-account modification are outside this model. Normal shutdown and real validation/write/commit/uncertainty failures add independent non-kill coverage. Existing read-only, permission-denied, corrupt and future-format fixtures retain all original database/marker/sidecar bytes and offer retry/exit.

Pending-commit feasibility is measured in the dependency qualification packet: locked `turso 0.8.2` accepts public `Builder::with_io_impl`; a test-only `turso_core 0.8.2` I/O wrapper delegates `PlatformIO` and arrests `-wal` `File::sync` while `tx.commit().await` is active. The inspected native source and `logs/process-kill.json` record five precommit kills reopening zero rows, five pending-WAL-sync kills reopening the whole inserted row, and five postack kills retaining it. This is a 15-trial synthetic feasibility probe, not any part of the required 360 application trials. No engine patch is needed. Freeze its source/configuration and lock identities in the dependency packet; keep the test-only direct core dependency/wrapper absent from release. Future application instrumentation must also have a releasable parent barrier and delegate every I/O operation unchanged after release.

Release one freezes current storage/backup version 1 fixtures and future-version rejection. Prior-release migration execution alone is inapplicable; a later data-format release requires new prior-format upgrade/interruption/failure evidence and a recoverable prior dataset.

## Private, restricted runtime

`C-SECURITY` combines exact production ACL/CSP/command/dependency/resource review with real forbidden-origin/window/command/shell/arbitrary-file tests. Custom-command ACL enforcement is mandatory. Malformed protobuf, invalid semantic values, semantically over-limit task payloads and backup documents reject natively before effects. SQL/markup-shaped values remain literal data. Instrumented fixtures exercise denials without introducing release automation commands; the delivered inventory proves their absence.

`C-OFFLINE` executes every installed-package journey under runtime network isolation. `C-PRIVACY` separately captures process-attributed networking across the full workload with networking available and blocked, including attributed WebView/helper processes and loopback. Start continuous capture before launch and end after exit; a known-connect external positive control must be detected and capture completeness demonstrated. OS-only traffic is separately classified. `fs_usage` network traces plus PID/socket lineage evidence may support the selected observer once qualified; `nettop` snapshots alone cannot rule out short-lived connections. Necessary observation permission is environmental evidence, never bypassed. A separate unprivileged account must actually fail managed-file reads; selected files do not authorize their parent directory. Modes/ACLs and symlink/hardlink aliases are checked.

`C-DIAGNOSTICS` exercises startup, storage failure, export/restore and version outcomes using unique sensitive text/search/path sentinels and a rare valid due date9999-12-31. Inspect all application-controlled logs/stderr/panic diagnostics for schema allowlist and zero seeded leaks. Rotation, restart, oversized-event and write/rotation-failure checkpoints verify five files at most 2 MiB each and total retained bytes <= 10 MiB. Logging failure cannot fail valid task work; no diagnostic upload occurs.

## Accessibility and handoff

`C-A11Y-KEYBOARD` records keyboard-only completion of every functional journey, native choosers, confirmation/draft dialogs, pending/errors, all query options and all result pages. Check visible unobscured focus, order, containment, Escape/cancel and meaningful return. `C-A11Y-VOICEOVER` records actual spoken names/roles/values/states, validation associations and async outcomes using the OS-bundled VoiceOver in the delivered WebView; record its build/settings. Automated DOM/AX inspection alone is insufficient.

`C-A11Y-VISUAL` measures rendered color pairs across the shipped light appearance and relevant focus/error/pending/status states, applying the selected criterion exceptions explicitly. Verify normal/large text and meaningful controls against 4.5/3/3 ratios. Use shipped Rust View Text size 100/150/200% controls and Command plus/minus shortcuts; per-launch default is 100%. Repeat all operations at 200% in 1280×720, with scroll access and no unreachable/clipped essential action. Browser-devtools CSS injection is not delivered resizing behavior.

`C-HANDOFF` ties every Must ID to complete positive/negative/boundary/recovery/performance and packaged/accessibility evidence at the delivered revision, includes package/source digests and raw outputs, and records independent observer/reviewer identities. Another developer follows clean build/verification prerequisites and commands; shipped help and compatibility/dependency documentation are checked. No missing/skipped/unexplained/wrong-host/mock-only result or unresolved Must violation is accepted as release complete. Harness selftests and specification probes are not Todo acceptance.
