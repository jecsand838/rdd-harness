## Accepted core

Collection, query, backup and workspace are distinct functional owners; supporting modules own mechanisms or presentation, never business invariants. Composition constructs/registers genuine generated providers without business-call or storage permission. Collection alone validates and normalizes task values for create, edit and restore. Identity is lowercase hyphenated UUIDv4, ordered by its unsigned 16 bytes. Title/query outer trimming uses Unicode 18 White_Space; title line breaks are LF, VT, FF, CR, NEL, LS and PS. Search applies NFC then full default non-Turkic case folding without rewriting stored text. UTC instants use signed 64-bit Unix seconds and integer nanoseconds 0–999999999; no chronological ordering is required. Status controls completed-time presence; editing Completed retains that instant.

Query combines status/date/text with AND and owns ordering and exact counts. Native workspace protects raw editor changes, including normalization-equivalent drafts; it retains submitted input and owns one pending task-mutation/restore slot until commit, confirmed rejection or reconciliation. Repeated activation of the same pending handle cannot reexecute; risky retry waits for reconciliation with committed state. Typed errors identify category, field/record and recovery without raw SQL or stack traces.

Backup v1 is UTF-8 JSON with exactly format_version:1 and tasks. Each task contains identity, title, notes, due_date, status, created_time, updated_time and completed_time; optional date/completed time use null, notes use an empty string when absent, status is Open or Completed, and instants contain seconds/nanos integers. Reject missing/unknown/duplicate keys, wrong types/version and duplicate identities before consent. Dates use strict YYYY-MM-DD within years 0001–9999. The same collection normalization validates imports; valid normalized exports round-trip exactly. Retain the immutable validated candidate, selected-file identity/label, counts and consent association; apply retained bytes/values without substituting changed file contents. Consent also binds current collection revision and is renewed if that revision changes.

Export snapshots one complete committed collection, independent of filters/drafts, including the old committed state while another mutation is pending. Restore replaces the collection atomically through collection. Destination checks include resolved paths and existing file identities for all managed database, recovery, migration and diagnostic files; unsupported replacement semantics reject before overwrite. No arbitrary byte cap may exclude valid 10000-task maximum-field content; decoded scalar limits apply after normalization and JSON escaping/whitespace does not count as task content. Actual storage/publication mechanisms require S5 proof.

## Supporting ownership and rights

`UI.*` render state, feedback, accessible focus/keyboard/contrast/resizing and literal text. `API.*` enforce declared wire/capability access, safe errors and outcome logging. `ST.*` provide embedded persistence, transactions, recovery evidence, preserved files/versioning/account permissions. `FS.*` provide selected-file grants/read/probe/publication/reconciliation/cleanup. `DT.*` provide instance/window events, installed resources/version and managed paths. `DG.*` implement required redaction, 10-MiB retention and nonblocking failure. `BL.Reproduce` covers reproducible Rust/tool/build prerequisites; `BL.Package` and `BL.Scope` cover packages and justified scope. `BL.Verify` covers evidence/check execution support, including the corrected hosted preparation lane; native package, privacy, accessibility and benchmark obligations remain required. None owns business invariants.

`CP.*` alone construct/register providers and handle initialization failure/shutdown without business calls/storage access. Entry callbacks belong to native_api; workspace consumes desktop events, preventing reverse dependencies. UI/build helpers need no invented services.

Call edges bind the exact union of provider-behavior operations. Keep snapshot, import validation, individual mutations and replacement distinct: query receives only snapshot; backup receives snapshot/validation/replacement; workspace receives initialization/individual mutations/outcome reconciliation. Collection alone calls storage. Failure/no-op identities may share their relevant operation without broadening rights. Type-only edges permit generated semantic imports without operations; storage owns raw persistence shapes, avoiding a storage→collection cycle. Composition binds genuine provider construction/wiring exports only, never dummy RPCs.

[FR-004](../../requirements/requirements.md#creating-and-editing-tasks) separates backup document parsing from collection task-value validation; backup delegates to `C.ValidateImport`. [FR-009](../../requirements/requirements.md#completing-and-deleting-tasks) separates workspace confirmation from collection deletion. [FR-016–018](../../requirements/requirements.md#mutation-feedback-and-coordination) separate collection committed history and storage outcome mechanisms from workspace pending intent and UI feedback. [FR-020](../../requirements/requirements.md#backup-and-restore) separates backup destination policy/consent from selected-files publication mechanisms. Repeated requirement allocations describe cooperation, not duplicate invariant authority; `CI/QI/BI/WI` remain exclusive.

Four owners separate cohesive task invariants, read semantics, transfer/consent and user intent. A module per field/screen/CRUD action would duplicate authority; generic common/rule-engine/clock domains add no requirement. Private time helpers remain permissible. S6 owns exact target homes/contracts/adapters; S5 proves mechanisms; S3 supplies independent oracles. This inventory claims no executed application acceptance.
