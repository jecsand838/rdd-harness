# Solution and interface specification

Requirements revision 5 and accepted [domain model](domain-model.md), [inventory](domain-inventory.json), [scenarios](scenarios.json), [constraints](constraints.md), [benchmarks](benchmarks.md) and [qualification](dependencies.md) remain authoritative. This document specifies their implementation arrangement and boundary semantics. The manifest supplies exact descriptor bindings, exports, target files and check inputs. No product implementation or application acceptance is claimed.

## Ownership and layout

One native Cargo package contains the four distinct functional modules and native supporting modules; its composition entry point wires providers. A separate Leptos CSR package builds Rust/WASM presentation. Both consume the existing standalone generated crate, excluded from outer workspace membership. Shared native compilation avoids speculative per-domain crates; private implementation submodules and executable import/call allowlists isolate owners. `pub(crate)` alone is insufficient. Architecture checks reject unauthorized generated methods, direct sibling implementation access, storage/SQL/filesystem access from UI, and construction exports used for business calls.

Each functional package is `todo.<owner>.v1`. Native_api, storage, selected_files, desktop and diagnostics also provide genuine generated services. UI, composition and build_support have no invented RPCs. Exported `service` symbols expose only generated trait implementations; `construct` builds their private providers and `wire` registers the native entry adapter. No private struct, storage connection, filesystem descriptor or task-domain type is exported. Composition may invoke only its nine approved construction/wiring exports. Each ordinary constructor takes application identity as `&'static str`, then one cloneable generated provider for each declared dependency in lexical owner order, and returns `Result<impl GeneratedService + Clone, OwnerFailure>`. Invalid identity or failed setup returns the owner failure; no partially registered provider escapes. Clones share ownership; dropping the final registered provider releases its resources. The platform export is exactly `native_api::wire<D, W>(identity: &'static str, builder: tauri::Builder<tauri::Wry>, diagnostics: D, workspace: W) -> Result<tauri::Builder<tauri::Wry>, native_api::Failure>`, with cloneable, static generated DiagnosticsService/WorkspaceService bounds. It privately constructs the generated Invoke provider, registers `todo_invoke` and returns only the builder. Registration installs the typed callback; it executes no business operation. The callback decodes InvokeRequest, exhaustively maps its nine action variants to the corresponding workspace RPC and nests that response in the matching Reply variant. Framework registration/managed state stays inside native_api; composition receives no provider internals. Immutable platform configuration derives from application identity during wiring without opening data, executing SQL or applying task operations. Startup and instance admission run through workspace, never composition.

Native providers use owned requests, `Send` futures and `Send + Sync`; consumers are concrete/generic. Tauri's named managed entry adapter may privately erase an owned async dispatch closure to register a non-generic command; its only public business surface remains generated Invoke. No extra network transport or in-process serialization is introduced. Actual frontend/native bytes cross only `todo_invoke`; every request is the generated native_api InvokeRequest, with a closed typed action union, and every reply is InvokeResponse. The nested response must match the submitted action. Permission to call an operation includes constructing and inspecting its generated request/response members, including nested action payloads, through that descriptor graph. It grants no calls to services owning nested messages. Other semantic type imports require the explicit type-only binding; consumer qualification constructs all nine native action variants without expanding S1 interactions.

## Data and validation

Collection is the sole authoritative task validator, including backup imports. Raw drafts retain exact strings, including invalid dates and normalization-equivalent edits. Draft due-date absence means clear; a complete draft replaces all three editable fields, so an omitted message is invalid. Storage uses its own raw row shape, avoiding reverse collection imports. Conversion into private validated values occurs once at collection admission and again when loading untrusted persisted rows; storage's typed transaction mechanism does not duplicate task invariants.

The accepted UUID, Unicode18, date, timestamp and strict JSON rules apply unchanged. Message presence is mandatory for required task timestamps, draft and action/outcome unions; zero/unknown enum selectors, malformed UUIDs, invalid nanos and missing required nested values reject. Empty notes is valid. Default empty response/outcome is never success. Unknown protobuf fields do not create permissions: recognized fields must form a complete valid action. No task-history ordering is imposed. Calendar selection uses the query owner's private native local-date reader; UI cannot select authoritative Today. Instrumented correctness builds may inject private readers; delivered builds expose no clock command.

No transport/document byte cap may exclude valid maximum-scalar collections or equivalent JSON whitespace/escaping. Backup parsing streams UTF-8/JSON, normalizes through collection, rejects duplicate/unknown/missing keys and malformed surrogate escapes, and bounds retained records/scalars by capacity/field rules. Selected-file reads use bounded chunks, not an artificial total-file ceiling. Native IPC similarly validates the declared action and decoded shape without a conflicting blanket payload cap. Reject exhaustion safely before any mutation; allocation/IO failure is an actionable failure, never truncation.

## Collection and storage operations

Collection Open initializes only genuinely absent data; otherwise it loads and validates existing state. ReadSnapshot returns one immutable committed revision; it remains available during a pending write and never exposes uncommitted rows. Query may only call ReadSnapshot. Backup may only call ReadSnapshot, ValidateImport and Replace. Workspace may only call Open, Create, Edit, SetStatus, Delete and ResolveOutcome. ValidateImport returns normalized values without persistence; Replace reuses the same validator under its atomic revision check, preserving imported history.

Create allocates a UUID only for the admitted operation; Edit replaces content while retaining identity/created/status/completed; SetStatus implements completion/reopening; Delete removes the selected confirmed identity. No-op edits/status changes preserve all timestamps and collection revision. Sample UTC at the successful transaction's final write preparation; a failed attempt establishes no creation/history. Each mutation uses a workspace-issued unique operation ID. The store atomically records effect, collection revision and durable operation receipt/fingerprint in one Turso transaction. Reusing an ID with different content rejects; repeating the same admitted operation resolves its receipt instead of executing again. A no-op acknowledgment records its outcome without changing task fields/revision. Receipt reconciliation need not return superseded task content; workspace re-queries current committed state.

Storage Open/Read/Commit/Outcome expose only parameterized raw operations. Commit admits a typed put/remove/replace with expected revision, serializes writers and acknowledges only successful durable commit. Whole replacement and its receipt are atomic. Use qualified WAL/synchronous FULL, local account-private files and one database-owning process. A dropped/canceled transaction must finish rollback before subsequent access. Definite precommit failure returns rejected; any uncertainty after dispatch remains uncertain until durable receipt/state reconciliation. Existing inaccessible, corrupt or future-format data is preserved with retry/exit, never automatically deleted/reinitialized. Revision exhaustion fails safely before mutation; it does not wrap. Release one freezes initial schema/backup format fixtures; previous-release migration is inapplicable, not tested green.

## Workspace and query

Workspace Open first obtains desktop instance admission. A secondary process activates the existing window and exits before collection Open. Primary startup opens collection and returns the default view. UpdateDraft records raw changed input; Navigate selects/new/cancel/restore/close/delete/clear/activate intent. Dirty navigation returns a one-use intent handle. DecideIntent retain cancels navigation; discard permits only that recorded action; delete confirmation identifies the selected task and permanent deletion. Cancel consumes the intent without effects. Handles are unpredictable 128-bit values, scoped to the native session and intent/candidate, and invalid after consumption/cancellation; unknown/stale/foreign handles reject.

Submit validates the session, activation and action, reserves the single pending task-mutation/restore slot before dispatch, and returns pending state. The same activation handle cannot execute twice. A completed deliberate new Create receives a fresh handle. Transfer's confirmed restore uses the same admission slot. ReadState polls state and attempts outcome reconciliation; viewing/search remains available while pending. Native work runs off the UI event loop. Pending feedback follows NFR-PERF-005, independent of whether a provider future has resolved. Confirmed rejection retains submitted input; uncertainty blocks risky retry. Cancellation of an IPC waiter does not cancel an admitted mutation or release its slot.

Normal close is an intent, then waits for a submitted operation: committed/reconciled-committed closes; rejection cancels close retaining input; uncertainty keeps waiting. Desktop Events provides activation/close events and approved window actions; entry callbacks route through the native adapter to workspace. No desktop→workspace business dependency is added. Restore success clears editor/selection and restores all defaults immediately. EvaluateView validates selectors, samples local Today and delegates the complete AND query; it returns exact ordered rows and both counts from one committed revision. Help comes from bundled resources/version through desktop and includes all FR-025 topics. Presentation renders text inertly and owns accessibility/focus mechanics, not business decisions.

## Backup and selected files

BeginExport obtains a specific native file selection and one complete committed snapshot, even while a mutation is pending. Its offer identifies unencrypted content and overwrite need. FinishExport cancel preserves destination; confirm binds the selected identity and starts publication. ResolveExport reconciles uncertainty before another publication attempt. UI labels may display the selected location; diagnostics never receive it.

BeginRestore occurs only after draft protection, reads and validates the complete selected file and retains immutable normalized values, file label/identity and current revision. FinishRestore cancel disposes the handle; confirm applies exactly those retained values. Changed source bytes cannot substitute another candidate. If current revision changed, return renewed counts/consent without replacement. Confirmation consumes the candidate only after a definite outcome; an uncertain restore retains correlation until reconciliation. No merge or restamping occurs.

SelectedFiles Select returns a scoped opaque grant, never unrestricted directory authority. Probe checks resolved paths and existing identities against all managed database/recovery/migration/diagnostic files; symlink/hardlink aliases reject. Only qualified local same-filesystem atomic replacement is supported. Publish begin creates a uniquely named private temporary beside the selected destination; append writes bounded chunks; finish verifies complete length/digest, flushes/synchronizes data, rechecks expected destination identity/consent and atomically renames. Preserve old destination on confirmed prepublication failure. Following process interruption, reconcile complete old/new hashes; neither partial bytes nor an unresolved outcome is reported successful. Cleanup removes only owned temporaries/consumed grants and never the destination. Unsupported guarantees reject before modifying an existing file.

## Errors, diagnostics and verification

Each generated response contains a success/failure outcome. Provider failures use declared schema codes; collection field/record errors propagate without SQL, stack traces or payload echoes. Native adapter failures separately cover malformed decoding, denied invocation, canceled waiter, unavailable lifecycle and absent/mismatched response. Capability checks run before dispatch. Missing messages/outcomes and unknown enum discriminants are tested on native/WASM paths. Diagnostic Emit accepts only severity/category/correlation/numeric outcome; the owner adds timestamp/version, validates codes, redacts, retains at most10MiB and cannot block valid operations on failure.

All 24 accepted product checks retain their scenario backlinks and exact result paths. Product runners, real providers/consumers, boundary-bypass tests, release packages and full rendered/input-ready oracles are implementation-produced resources. Their commands and prerequisites are frozen now; disposable qualification never reports their scenarios passed. Per-module implementation checks consume the actual owned Rust source; preparation must schedule provider, consumer, composition and type-import proofs at first delivery and cumulatively.

Canonical generation and disposable signature rejection use the protected driver on native and WASM. Additional qualification checks exercise source ownership/import rights, construction exposure, immutable fixture reproduction, fresh tool acquisition, native/UI/package integration, host facilities and exact-source receipt transfer. Replay inputs are versioned under `.rdd/sources/s6`; runners copy them to owned scratch before building. D1 bytes/oracle arrays retain accepted hashes; the complete Unicode18 normative normalization corpus and C/F mappings remain required product inputs, not S5's sampled256 NFC rows.

The original v6 observer remains unchanged and guards its historical installed carrier. A fresh package observer is built from that reviewed source with only explicit expected path/hash/bundle substitutions recorded in a separate identity manifest; actual trust is checked, never inherited by assumption. UI actions require the parent's explicit authorization for that exact manifest. Missing trust/observations or resources fail readiness. Package marker timing qualifies only the external mechanism; product benchmarks still require complete independent rendered/input-ready oracles, sampling and reference conditions. Provided macOS/SDK baseline, fresh Rust/Buf provisioning and package evidence retain distinct claims.

## Qualification order and reproduction

Run these checks from the exact committed candidate on the declared native host. `C-READY-TOOLS` installs into empty owned homes when needed, verifies official archive/executable identities and links a native and WASM smoke. Build commands use its recorded toolchain, a separate build Cargo home, pinned CLI directory and the compiler's own `lib` directory for dynamic-library lookup; they never modify the qualified installation. The provided SDK/OS are measured baseline inputs, not freshly provisioned operating systems.

| Check | Input/output and prerequisite timing |
|---|---|
| C-QUAL-CONTRACTS | Exact nine schemas, generator and locks; protected driver compares all generated bytes, compiles native/WASM providers/consumers and rejects request/response/signature/error mutations. |
| C-QUAL-BOUNDARIES | Exact descriptor index and bindings; disposable constructors retain typed dependencies, register/invoke the entry, reject explicit forbidden consumer calls/private exports/wrong providers, and release final ownership. It does not prove real adapter adoption or all indirect-call bypasses. |
| C-QUAL-FIXTURES | Immutable D1 recipe/bytes/oracle arrays and full Unicode18 corpus; byte reproduction and input inventory precede all product oracles. |

Its supplied checkpoint and runtime observations are external preconditions, not ignored substitutes for frozen runner/source/fixture inputs.
