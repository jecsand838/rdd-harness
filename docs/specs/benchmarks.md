## D1 recipe

Seed is ASCII `rdd.todo.d1.r5.v1`; nominal date is 2026-10-27. Generate variants V=`A`,`B`, each i=0…9999 in increasing index order:

- UUID bytes are the first 16 SHA-256 bytes of ASCII `seed:V:iiiii`, where `iiiii` is five-digit zero-padded decimal i. Set byte 6=`(byte 6 & 15) | 64`, byte 8=`(byte 8 & 63) | 128`; encode lowercase hyphenated UUID. Assert all 20,000 identities distinct.
- Title begins `V task iiiii`, using uppercase `TASK` for odd i. Append ` Café` when i%10=0 and ` [x]*` when i%100=0, then right-pad with `t` to 80 scalars.
- Notes begin `V note iiiii`; append ` cafe` followed by U+0301 and ` Straße` when i%10=0, and ` notes-only-key` when i=42. Right-pad with `n` to 256 scalars. Spaces shown are literal. Exactly 10% of each text field includes non-ASCII.
- Created instant is seconds=`1700000000+floor(i/4)`, nanos=0, producing ties. Status is Completed iff i%5=0. Completed time is created seconds+10/nanos0 for Completed, otherwise null; updated equals completed when present, otherwise created.
- Due bucket=`floor(i/5)%4`: 0=null, 1=2026-10-26, 2=2026-10-27, 3=2026-10-28. Each bucket has 2,500 tasks, independently 2,000 Open/500 Completed; total 8,000 Open/2,000 Completed.

Use exactly the v1 document/task keys in [domain model](domain-model.md). Serialize UTF-8 JSON with recursively sorted object keys, no ASCII escaping, separators comma/colon without spaces, and one final LF. Both input files contain 5,729,031 bytes.

## Independent oracle

Let U(i) be the frozen UUID. Status/date sets follow the recipe predicates; query/status/date constraints intersect. No-date selects bucket0; Today selects nonnull date equal to externally observed local T; Overdue selects Open with nonnull date<T. T is independently recorded before/after each sample; a changed date invalidates that sample environmentally. Stored dates and frozen nominal input bytes never change.

Search sets: `zero-match-❌` and `cafe` return empty; `task` returns all; `V task 00042` and notes-only `notes-only-key` return U(42); `[x]*` selects i%100=0; decomposed café and `STRASSE` select i%10=0. Case variants have the same sets under pinned Unicode18 vectors in S3. Blank query selects all. Independently frozen orders are created descending/ascending then UUID bytes ascending; due order is dated ascending, null last, then created descending and UUID ascending. Every filtered order is the matching subsequence. Implementation query/comparator/Unicode helpers cannot generate expected results.

## Workloads and boundaries

P1: D1A, normal exit between launches, OS caches retained. Five unmeasured warm-up launches then 30 measured. Stop at correct usable default Open/empty-search/Any/newest view, count 8,000; record p50/p95/max for `launch_ms`, p95≤2000ms.

P2: reset outside each sample. Each of nine classes gets 10 warm-ups then 100 measured. Create removes i9999 before timing and submits its 80/256-scalar content, accepting a new distinct UUID. Edit changes i42 title's first character to Z; complete starts Open i6; reopen starts Completed i5; delete targets i42 and starts after confirmation. Observe mutation persistence acknowledgment and correct active-view result. Each `create_ms`, `edit_ms`, `complete_ms`, `reopen_ms`, `delete_ms` p95≤200ms.

Query classes start from different active values: cycle search through zero/one/many/punctuation/STRASSE/decomposed-café/notes-only queries; status Completed/All/Open; date Today/Overdue/No-date/Any; order oldest/due/newest. Each `search_ms`, `status_filter_ms`, `date_filter_ms`, `ordering_ms` p95≤250ms. Search includes debounce. Reset fixture/control state so every timed action changes the requested value.

P3: three warm-ups for export and three for restore, then 30 measured exports and 30 measured restores. Export starts after selection/overwrite confirmation. Restore starts with selected-file validation; pause only while awaiting user confirmation, resume on confirmation dispatch. Alternate disjoint A→B→A, resetting outside timing. Stop after durable publication/commit and correct rendered default view. `export_ms` and `restore_ms` separately have p95≤5000ms. Independently parse/compare every output/restored complete identity/field map; preserve Completed history and require immediate view reset. A no-op or merge fails.

## Evaluation and evidence

Nearest-rank percentile selects sorted sample ceil(q×n), one-based. Keep all valid slow samples, separately labeled warm-ups and failures; each operation error fails correctness. A 30-second operation timeout fails; check timeout≤7200seconds is inconclusive, never pass. Independently documented environmental/instrumentation failure permits labeled replacement measurement, retaining original logs; threshold failure never justifies exclusion/retry-until-pass.

Runner stdout contains exactly one benchmark JSON object: `errors`, separate `samples` series above, matching `units`=`ms`, and actual `environment`; progress goes to stderr. Record command, evaluator/input hashes, host profile/qualification, all event/raw samples, warm-up/invalidation reasons, source/package identity and exact scenario outcomes under declared results paths. Samples contain measured operations only. The independent evaluator rejects duplicate keys/nonfinite values and enforces exact valid sample counts, units, errors, nearest-rank limits and semantic correctness. Skipped, omitted, filtered or unqualified checks remain unverified.
