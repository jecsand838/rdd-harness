# Rust contract generation

## Supplied implementation

`tools/proto-codegen` is a standalone Rust tool with exact Prost-family dependency versions. It consumes a standard `FileDescriptorSet`, uses Prost's own resolved Rust names/types, and emits:

- Message/enum bindings under `gen/rust/src/generated/`.
- Nested package modules in `gen/rust/src/lib.rs`.
- A local trait for every unary Protobuf service returning `impl Future<Output = GeneratedResponse> + Send`.
- A descriptor-derived source/service/method/message/enum/Rust-symbol index in `.rdd-generated.json`, with shared support files accounted separately.
- A small standalone generated crate depending only on `prost` and `prost-types`.

Every service response declares schema-owned success/failure outcomes; there is no provider-defined associated error type. Entry-adapter decoding, size limits, cancellation and lifecycle errors have separate frozen mappings. Presence and business validity still need semantic tests. Use concrete or generic consumers: return-position future traits are not automatically dyn-compatible. The trait's `Send + Sync` bound is appropriate for the supplied native service pattern. WASM UI code can consume generated messages without implementing the native provider trait. If specification requires non-Send providers or streaming services, amend and qualify the generator explicitly; the current tool rejects streaming instead of silently generating the wrong interface.

`tools/rdd/proto_traits.py` runs Buf lint and descriptor compilation without invoking a shell, compiles generated bindings and every descriptor-derived message/enum import, and compiles temporary valid and deliberately invalid providers. Negative proofs deliberately violate request, response, method signature and error-boundary types; they must fail for the intended compiler diagnostic after the valid provider and consumer compile. Proof implementations stay in ignored runtime scratch, not generated production bindings. Type-only domain imports use this same compiler qualification without artificial RPCs. The manually invoked `selftest` remains separate and never runs in CI.

The checker then compares the regenerated bytes with committed output. `--write` publishes only a successfully checked candidate and refuses to replace a nonempty directory without its generated-ownership marker. It preserves a prior generated tree if publication fails. Missing tools/locks are reported as blocked, never as successful checks.

Subprocess output is captured within a fixed budget and deadlines terminate the owned process group. Buf source traversal disables symlink following; local contract and generator source symlinks are rejected. Descriptor reading is bounded before decoding. These checks protect the generation process; they do not replace the frozen input inventory.

## Bootstrap and later checks

Install the repository-documented Rust and Buf versions and the WASM target required by the Rust frontend. From the repository root:

```sh
./rdd contracts generate --bootstrap-lock --target wasm32-unknown-unknown
./rdd contracts check --target wasm32-unknown-unknown
```

The first command resolves missing `tools/proto-codegen/Cargo.lock` and `gen/rust/Cargo.lock`; inspect and commit them. Later commands use `--locked`. If a dependency amendment changes the generator manifest, deliberately update locks and rerun qualification during specification. Do not use missing locks or a dependency network outage as a reason to remove `--locked` in a frozen run.

Use `--against` with the actual accepted Buf baseline input for amendment checks, for example a retained descriptor or an approved Git ref/subdirectory. Do not guess that `main` is the accepted contract baseline. The host compile always runs; repeated `--target` options add other installed targets. Specification qualifies disposable consumers/providers and dependency experiments on required targets. Actual frontend/native application/package conformance belongs to implementation and must have planned producers and first-due phases; it cannot be a specification prerequisite.

The generated crate intentionally has its own `[workspace]` for isolated verification. In an application workspace, exclude it from the outer workspace's member globs and consume it through path dependencies, or amend the generator layout during specification. Do not let broad `gen/*` globs create competing workspace roots.

## Minimal Buf configuration

The repository supplies root `buf.yaml`; this is the expected v2 shape:

```yaml
version: v2
modules:
  - path: contracts
lint:
  use: [STANDARD]
breaking:
  use: [FILE]
```

`buf build --as-file-descriptor-set --output <file>` supplies the standard descriptor consumed by `Config::compile_fds`. That Prost API does not invoke `protoc`; Buf is the schema compiler in this route. Add approved external schema dependencies to Buf's configuration/lock and the specification inventory.

A community `protoc-gen-prost` Buf plugin is an alternative message generator. Its upstream examples also show optional Serde and tonic plugins. Do not copy an entire example into this local application: tonic adds a transport the baseline does not need, and message generation alone omits local service enforcement. If switching routes, pin plugin versions, use their own current compatibility documentation, and retain signature and native/WASM tests.

## Limitations and evidence

The generator supports unary services. Native and requested-target compilation, generation drift, and signature rejection are concrete checks. They do not establish business behavior, installed package correctness, adoption of traits by real modules, or wire/semantic compatibility by themselves. The result JSON explicitly records this scope and command-log digests for the controller to index.

This repository's production-app contracts are authored by the specification workflow. The harness's example `rdd.v1` schema is only a bootstrap/verification fixture; it is not the Todo domain API.
