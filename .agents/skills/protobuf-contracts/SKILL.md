# Protobuf contracts

Read the active workflow authority. Specification owns interface design, canonical generation, qualification and amendments. Preparation and implementation consume the frozen bundle and may regenerate only into disposable verification output. Any changed field, operation, generated byte or semantic mapping is a specification blocker, including wire-compatible additions.

## Procedure

1. Derive every architectural module from a functional subdomain covering all its allocated FRs. Record provided fully qualified services, consumed operations, allowed dependencies and exact owned paths. Map every public method to a requirement-derived solution operation and consumer. Private Rust helper modules do not need standalone contracts. Specify cohesive module interfaces and the local UI-facing API. Define operation input/output, error meanings, ownership, validation, presence, ordering, limits, idempotency, admission, commit point, and cancellation separately from wire syntax.
2. Use versioned packages, stable field numbers, explicit optional/oneof choices, safe enum defaults, and reserved deleted field numbers/names. Never reuse a tag. Model calendar dates distinctly from UTC instants and preserve unknown/invalid input handling at native boundaries.
3. Pin Buf, Rust, Prost, generator source/configuration, and dependency locks. Qualify generated native and Rust/WASM consumers together. Keep generated messages free of Tauri, storage, and network runtime dependencies.
4. Generate messages, local unary service traits and the descriptor-derived symbol index in existing generator metadata using Prost-resolved names. Traits return `Future<Output = GeneratedResponse>`; schema-owned response variants carry declared success and failure outcomes, with no provider-defined associated error type. Freeze entry-adapter decoding, limits, cancellation and lifecycle failures separately. Use concrete/generic local callers compatible with these traits, without redundant in-process serialization.
5. Separate specification qualification from implementation conformance. Qualify each module with disposable providers/consumers, positive compilation and deliberate request/response/signature/error-boundary rejection on required targets. Plan real adapter registration, provider/consumer binding, dependency/visibility and bypass tests for their first implementation phase and cumulatively thereafter. Test absent outcomes, unknown enums, invalid defaults, presence, normalization and specified errors; generated values do not establish business validity. Keep private invariant-owning domain types where needed.
6. Freeze the exact source/import closure, generated inventory, shared support files, derived symbols, generator/configuration inputs, dependency locks and linked semantics during specification. Downstream reproduction must match exact bytes/inventories. Buf compatibility checks support authorized amendments against the accepted baseline and cannot establish immutability. Never publish changed bindings or edit generated Rust to match implementation.

## Commands

Run from the repository root. Use these only in the authorized workflow stage:

```sh
# First authorized generation: resolve locks, generate, and compile.
./rdd contracts generate --bootstrap-lock --target wasm32-unknown-unknown
# Subsequent deterministic verification; no generated-source mutation.
./rdd contracts check --target wasm32-unknown-unknown
```

Commit the generated crate and both Cargo.lock files after first qualification. Missing Rust/Buf/target/dependency access is blocked evidence. Read [contract design](references/contracts.md) and [generation](references/generation.md) before selecting adapters or changing generator behavior.
