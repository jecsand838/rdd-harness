# Specification workflow

Read `AGENTS.md`, the [specification command sequence](../../../docs/harness/workflow-guide.md#stage-one-specification), and the [artifact guide](../../../docs/harness/artifact-guide.md). Run `./rdd status --brief` and `./rdd doctor`; initialize only missing run/index/draft artifacts. Register every actual author and match the manifest inventory. Registration declares provenance, not authenticated execution.

Treat `requirements/requirements.md` as product authority; preserve its text unless the user requests an amendment. A draft label does not require another permission round after the user accepts the input. This stage selects the complete domain/behavior inventory, target architecture and contracts; it does not author production behavior or implementation phases/tasks. Load [amend-requirements](../amend-requirements/SKILL.md) for amendment impact and [context-integrity](../context-integrity/SKILL.md) for source handling. Regeneration archives derived artifacts without deleting user data or silently replacing an existing application.

Use S0–S8 from `workflow nodes/next`, exact [native specialist owners](../../../docs/harness/codex-runtime.md#runtime-contract), bounded claims and recorded handoffs. S1 owns domain inventory, S2–S4 verification design, S5 qualification, and S6 reconciliation/contracts. Ground each packet in actual file inventories, the current artifact schema and command `--help`; return upstream corrections to their authors. Follow [draft size guidance](../../../docs/harness/artifact-guide.md#draft-size) before authoring and at handoffs. Keep the coordinator plus at most two authors and a read-only reviewer; unavailable profiles are capability blockers. Requested model settings do not attest the backend.

## Procedure

1. Generate the requirement index without rewriting authority. Read complete normative vocabulary, global rules, acceptance text, platform/benchmark sections and all FR/NFR IDs; link original source locations and reject duplicate IDs/dangling references. Inspect current architecture, APIs, migrations and accepted evidence when reusing a baseline.
2. Load [rdd-spec-grill](../rdd-spec-grill/SKILL.md) for consequential choices throughout authoring. Capture actual qualified direction, resolve accepted choices' originating questions before affected claims/handoffs, and publish through the artifact owner. Do not turn assumptions into normative requirements or hide material TBDs.
3. Use [research-dependencies](../research-dependencies/SKILL.md) and the relevant Rust/Tokio/Tauri/Turso skills to qualify actual compatible versions, UI packaging, persistence/async behavior, tooling, hosts and evidence transfer. S5 records reproducible dependency/mechanism experiments and explicit gaps; S7 qualifies the complete exact candidate. Synthetic transfer proofs establish the mechanism only. A cached executable or tutorial does not establish clean-host readiness.
4. Apply [domain-boundaries](../domain-boundaries/SKILL.md) to S1 inventory and S6 reconciliation: distinct functional owners, explicit support owners, invariant ownership, directed interactions and complete target homes for application/build/tests/fixtures/evaluators/packaging/docs. Keep framework adapters from defining business domains; justify every split and reject speculative abstractions.
5. Specify observable preconditions, postconditions, state transitions, normalization, errors, retries, cancellation, concurrency, atomicity and time semantics. Allocate every requirement to solution elements. Keep each rule authoritative in one place and reference it elsewhere.
6. Author and audit the complete S3 catalog using the [scenario template](../../../.rdd/templates/scenario.md), with independent golden oracles for every functional requirement and positive behavior and reciprocal FR links. Include required negative, boundary, interruption, concurrency, regression, accessibility and privacy cases; record through the S3 validator before handoff. Use the [benchmark template](../../../.rdd/templates/benchmark.md) for NFR protocols, retaining explicit skip policy; declare complete runner/input/tool/host prerequisites and timing. Unsupported required platforms remain blockers.
7. Use [protobuf-contracts](../protobuf-contracts/SKILL.md) to compile and freeze the exact sources/imports, generated messages/traits, descriptor symbols, generator configuration and locks. Preserve every accepted S1 identity/binding and qualified response/error semantics. Disposable provider/consumer proofs cover required targets and invalid signatures/values; separate real provider/consumer/bypass checks belong to implementation. Private helpers need no artificial contracts, network calls or serialization. Downstream reproduction compares exact bytes and inventories, including rejection of compatible additions.
8. The S6 owner follows the [snapshot publication/refresh procedure](../../../docs/harness/artifact-guide.md#refinement-records). Commit the complete candidate, run validation/readiness and obtain both [independent perspectives](../phase-review/SKILL.md#specification-and-preparation-reviews). Semantic review follows requirements through decisions, owners, contracts and oracles; execution review follows every prerequisite through clean provisioning and actual hosts/transport. Shape validity is insufficient.
9. Preserve findings and independent resolutions, rerun affected proofs and re-review changed candidates until both perspectives approve the same identity with zero unresolved findings. Missing evidence or exhausted budgets leaves the workflow incomplete. Freeze through the controller and commit outputs; keep receipts outside the source inventory they certify.

## Exit conditions

Every requirement has solution/verification coverage; every boundary has an enforceable owner/interface; NFRs have measurable protocols, including necessary human evidence. Target architecture, check execution design and the exact qualified contract bundle are frozen with current independent approval. The controller accepts the freeze. Downstream frozen-specification defects require a critical regression record, preventive-control repair and reproducing regression; preparation/implementation cannot invent missing semantics.

If infeasible, retain concrete evidence and the smallest unresolved decision. Use the existing specification/scenario/dependency/decision templates and [worked example](references/specification-example.md); do not weaken requirements to satisfy tooling.
